## What changes

**Before:** a region at WATCH or above was CONFIRMED after the required number of consecutive report days, under the
same regime, method set and measurement support.

**Now:** it also needs **every included method, a zero-scored one included**, to show that number of distinct retained
observations across those report days.
- A report that repeats the previous report's observation counts as a report day. It is not a new observation.
- Report days are still counted and shown as before (`consecutive_days`).

**Contract version.** The contract moves from v1 to `method-comparability-v2`.
- No v1 report day counts toward a v2 confirmation.
- So on the first v2 run, a region at WATCH or above records the reset as `REPORT_DAYS_BELOW_REQUIRED:REGIME_TRANSITION`
  instead of carrying its earlier days.
- This is a disclosed transition, not a data outage.

## What counts as a new observation

| method | identity, from retained evidence only | a new observation | not a new observation |
|---|---|---|---|
| LG (candidate) | `measurement.observation_day`, with `input_sha256`, `input_selection_sha256` and `operator_identity` | a later observation day | the same day with the same digests (**repeated input**); the same day with different digests (**revision**) |
| THD | Selected station and measurement identity; returned trace epoch and raw-sample SHA256 from retained provider evidence. An update is a later actual returned endpoint under unchanged support. Requested windows are consistency checks, not observations. Missing evidence is UNKNOWN; same-epoch changed content is a revision, not an update. | a later actual returned endpoint | the same returned trace, or a later request alone |
| any other | none registered | — | always **unknown** |

**Never read as evidence of a new observation:**
- retrieval or download times, file modification times;
- report or publication times;
- calibration or recalibration dates;
- an HTTP 200 that returned unchanged content;
- a later requested window.

An unknown identity blocks confirmation. So does an observation earlier than the previous report's.

## Known consequence

**Kaikoura.** Its THD record comes through the bound-station route (IU.SNZO), which does not yet retain a raw-sample
digest.
- Under this rule, a Kaikoura row at WATCH or above cannot be confirmed, and states "THD observation identity missing
  from the retained evidence". It does not mean there was no measurement.
- Kaikoura's values, scores, tier and issued history are unchanged. Its last issued CONFIRMED label stands as issued.
- A separate writer repair is owned to record that digest prospectively. No digest will be invented for history.

## What a reader sees

- **Report JSON:** `persistence.regime` carries `report_days`, `report_days_met`, `confirmation_rule`, per-method
  `observation_updates` (epochs newest first, steps, update and revision counts) and `not_confirmed_reasons`.
- **Pages region card:** regions at WATCH or above get one line, for example: "Not confirmed: 2 report days; LG 1
  observation (latest 2026-10-19); THD 2 observations — LG repeated input (the same observation as the previous
  report)".
  - When too few report days remain, the line says why: no report on the previous day, rule change, method set changed,
    measurement support changed, previous day below WATCH, or no earlier report.
  - Regions below WATCH get no confirmation line.
  - A report issued before this rule keeps its label and gets no inferred reason.
- **Raw-history download:** the same flag, report days, observation counts and reasons, copied from the issued report.
  Nothing is recomputed.
- **Hosted Explorer:** the CONFIRMED/PRELIMINARY flag follows this rule from the first v2 report. The hosted explanation
  line ships in its own hosted stage, recorded separately.

## What this does not claim

- Distinct observations are **not** statistically independent evidence. Adjacent LG epochs share most of their input
  window.
- Confirmation is a persistence label. It does not measure physical cause or predictive value.
- It does not make the GNSS observations any fresher.
